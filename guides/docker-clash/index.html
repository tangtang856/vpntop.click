利用 Docker 容器部署 Mihomo / Clash 打造内网代理服务器

📅 更新时间：2026年11月 💻 适用环境：进阶开发者环境 ⏱️ 阅读时长：约 5-8 分钟实操
💡 教程导读与核心目的

对于拥有 NAS、树莓派或家庭小型 Linux 服务器的用户，利用 Docker 容器化运行代理，既不需要刷路由器，又能提供全天候稳定的局域网 HTTP/Socks5 出口。

图文实操步骤分解

第一步：编写 docker-compose.yml 配置文件

创建 clash 目录，编写基于 metacubex/mihomo 镜像的 compose 文件，映射 7890 端口与 web 仪表板端口。

第二步：挂载 config.yaml 机场配置文件

将下载好的机场配置放置在宿主机的挂载卷目录下，核对外部控制端口 secret 密钥。

第三步：启动容器并通过浏览器 Web UI 管理

执行 docker-compose up -d 启动，在局域网浏览器输入 http://IP:9090 即可图形化切换节点与查看流量。

常见报错排查技巧 (Troubleshooting)

1. 节点全部超时或 Ping 为 Timeout： 首先检查电脑或手机的【系统时间】是否精确对齐网络标准北京时间。时间偏差超过 90 秒会导致 TLS 握手彻底失败。其次检查订阅链接是否已过期或流量耗尽。

2. 能打开 Google 但微信图片加载不出来： 说明误开启了【全局代理 (Global)】模式。请在代理设置中切换回【规则 (Rule)】模式，让国内流量自动绕过代理走本地直连。

3. 提示 Port already in use 端口被占用： 通常是由于旧的客户端后台进程没有退出彻底，或与其他加速器冲突。在任务管理器中结束对应进程，或在设置中将端口从 7890 修改为 7892 即可解决。
